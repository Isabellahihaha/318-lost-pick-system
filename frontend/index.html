For developers — data & integration notes

This screen now talks to the real lost-service and found-service Spring Boot APIs via DataStore — nothing else in the page knows the backend exists. Login is still a local placeholder (no user-service yet), so items are tagged with whatever username you typed in.

Lost/Found item response shape (both services)
{
  id: number,
  name: string,
  category: string | null,
  description: string,
  location: string,       // regional vicinity, free text
  eventDate: string,      // e.g. "14 Sep 2026" — stored as text, not a Date
  contactEmail: string,
  ownerUsername: string,
  resolved: boolean,
  createdAt: string       // ISO instant
}
Endpoints in use
Method & pathUsed by

GET http://localhost:8081/api/lost-itemsRequest page

PUT / DELETE …/{id}Not wired into this UI yet, but live on the API

Recommendations on the Dashboard are computed client-side for now (word-overlap match against your own posts/requests) — see DataStore.getRecommendations. A Gemini-backed endpoint can replace just that one method later.
